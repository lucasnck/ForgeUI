## Criteria

- [x] Given a size, tone or weight value, the recipe sets the matching custom property and the consumer renders the matching token value; no literal font size, weight or color appears in any consumer module.
- [x] Given `size`, `tone` and `weight` all passed, each one resolves independently and none overrides another.
- [x] Given a consumer default size, tone or weight, an explicit prop wins and the default applies only when the prop is absent.
- [x] Given a semantic heading default (`--heading-*`), an explicit `size` or `weight` prop wins without depending on declaration order in the stylesheet.
- [x] Given `ComponentTextTone`, no value maps to a missing token, and `warning`/`info` are absent until matching text color tokens exist.
- [x] Given the recipe, every declaration is a token reference, and `npm run test:tokens` passes with no numeric or color literal.
- [x] Given the four themes and forced colors, text colors resolve through the semantic tokens without a component-level override.
- [x] Given both consumers, the same recipe serves body text and headings without a duplicated size or weight declaration.
- [x] Excludes element semantics and rendered tag choice (component-owned), layout and spacing, copy and localization, font asset loading and font-family switching, and the control size scale (`ComponentSize`), which measures control heights, not text.
- [x] All nine declarations live in `types/typography.ts` and are exported by `@/design-system`.
- [x] Components extend these interfaces; they never inline a size, tone, weight, level or element union.
- [x] The `size` xs…7xl contract uses `--font-size-xs`…`--font-size-7xl`; One value per existing step, in the same order.
- [x] The `tone` default / muted / brand contract uses `--color-text-default` / `--color-text-muted` / `--color-text-brand`; .
- [x] The `tone` danger / success / inverse contract uses `--color-text-danger` / `--color-text-success` / `--color-text-inverse`; .
- [x] The `weight` regular / medium / semibold / bold contract uses `--font-weight-regular` / `--font-weight-medium` / `--font-weight-semibold` / `--font-weight-bold`; .
- [x] The `level` 1…6 contract uses `--font-size-*`, `--line-height-*`, `--font-weight-*`, `--letter-spacing-*` per heading step; Mapping is owned by [Heading](../components/atoms/Heading.sc.md).
- [x] The Default size / tone / weight contract uses `md` / `default` / `regular`; Resolved by the shared recipe when the consumer passes no explicit value.
- [x] The recipe exposes two tiers of custom properties so an explicit `size`, `tone` or `weight` always wins over a semantic default without relying on declaration order.
- [x] The excerpt shows one representative value per family; the delivered recipe declares every value from the table above, plus local custom-property resets that prevent nested consumers inheriting another component’s selection.
- [x] Consumers compose `text`, `size`, `tone` and `weight` and reuse the single set of declarations in `text`.
- [x] `--heading-*` properties are written by [Heading](../components/atoms/Heading.sc.md) for its level defaults and reset locally by [Text](../components/atoms/Text.sc.md).
- [x] Consumers compose it and declare no literal font size, line height, weight, letter spacing or text color:
- [x] Every declaration in the recipe is a token reference or a structural keyword, so no numeric or color literal is introduced and no theme-specific rule is required.
- [x] The capability adds no motion, so no reduced-motion alternative applies.
