
```js
const path = require("node:path");
const OUTPUT_FILE = path.normalize("src/design-system/helpers/icon-data.generated.ts");
function renderModule(_manifest, records) {
  const body = records.map(record => {
    const paths = record.paths.map(d => `      ${JSON.stringify(d)},`).join("\n");
    return `  ${JSON.stringify(record.name)}: {
    name: ${JSON.stringify(record.name)},
    viewBox: ${JSON.stringify(record.viewBox)},
    drawing: ${JSON.stringify(record.drawing)},
    paths: [
${paths}
    ],
  },`;
  }).join("\n");
  return `import type { IconGeometry } from "../types/icon-geometry";

export const iconData = {
${body}
} as const satisfies Readonly<Record<string, IconGeometry>>;
`;
}
```

## Tests

- V2 Supported icon geometry: verify valid/boundary input/output and minimal consumer code against the actual helper signature.

- Regeneration is deterministic and stale generated data fails validation.
- Missing assets, duplicate names and unsupported SVG attributes identify the offending file.
- Manifest provenance and license remain present after changing vendors.
- Source checks reject runtime vendor packages and raw asset imports.
- Generator output matches the canonical IconGeometry type.

## Criteria

- [x] Names remain canonical; vendor names and provenance are confined to the manifest.
- [x] Generated data moves to helpers/icon-data.generated.ts and uses types/icon-geometry.ts.
- [x] Committed normalized geometry makes generation reproducible offline.
- [x] Each asset has one manifest entry, a 24-unit viewBox and normalized paths.
- [x] Validation rejects stale output, unsupported attributes and runtime vendor dependencies.
- [x] Changing sources requires only manifest, assets and regeneration; public Icon props stay stable.
- [x] Failures name the file and the normalization rule.

- [x] V2 **Supported icon geometry** is covered through the public Icon consumer examples and typed caller fixtures: Use valid iconData names through Icon and typed caller fixtures, reject unsupported names, and retain canonical geometry ownership without copying SVG data into V2.
- [x] V2 imports only the actual helper export or documented public helper subpath, keeps typed data valid and documents output ownership. No standalone helper route/kind, private dependency or duplicated implementation is introduced; this pending item is consumer acceptance, not loss of existing API availability.
