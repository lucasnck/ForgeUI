## Content

```ts
const CPF_RAW = /^[0-9]{11}$/;
const CPF_DISPLAY = /^[0-9]{3}\.[0-9]{3}\.[0-9]{3}-[0-9]{2}$/;
const CNPJ_RAW = /^[A-Z0-9]{12}[0-9]{2}$/;
const CNPJ_DISPLAY = /^[A-Z0-9]{2}\.[A-Z0-9]{3}\.[A-Z0-9]{3}\/[A-Z0-9]{4}-[0-9]{2}$/;

export function normalizeCpf(value: string): string {
  const text = value.trim();
  if (text === "") return "";
  if (CPF_RAW.test(text)) return text;
  if (CPF_DISPLAY.test(text)) return text.replace(/[.-]/g, "");
  throw new RangeError("Invalid CPF format");
}

export function formatCpf(value: string | null): string {
  if (value === null) return "";
  const raw = normalizeCpf(value);
  if (raw === "") return "";
  return `${raw.slice(0,3)}.${raw.slice(3,6)}.${raw.slice(6,9)}-${raw.slice(9)}`;
}

export function normalizeCnpj(value: string): string {
  const text = value.trim().replace(/[a-z]/g, letter => letter.toUpperCase());
  if (text === "") return "";
  if (CNPJ_RAW.test(text)) return text;
  if (CNPJ_DISPLAY.test(text)) return text.replace(/[.\/-]/g, "");
  throw new RangeError("Invalid CNPJ format");
}

export function formatCnpj(value: string | null): string {
  if (value === null) return "";
  const raw = normalizeCnpj(value);
  if (raw === "") return "";
  return `${raw.slice(0,2)}.${raw.slice(2,5)}.${raw.slice(5,8)}/${raw.slice(8,12)}-${raw.slice(12)}`;
}

export function isValidCpf(value: unknown): boolean {
  if (typeof value !== "string") return false;
  let raw: string;
  try { raw = normalizeCpf(value); } catch { return false; }
  if (raw.length !== 11 || /^([0-9])\1{10}$/.test(raw)) return false;
  for (let length = 9; length <= 10; length++) {
    let sum = 0;
    for (let index = 0; index < length; index++) sum += Number(raw[index]) * (length+1-index);
    const remainder = sum % 11;
    const digit = remainder < 2 ? 0 : 11-remainder;
    if (digit !== Number(raw[length])) return false;
  }
  return true;
}
export function isValidCnpj(value: unknown): boolean {
  if (typeof value !== "string") return false;
  let raw: string;
  try { raw = normalizeCnpj(value); } catch { return false; }
  if (raw.length !== 14 || /^([0-9])\1{13}$/.test(raw)) return false;
  const weights = [[5,4,3,2,9,8,7,6,5,4,3,2], [6,5,4,3,2,9,8,7,6,5,4,3,2]];
  return weights.every((row,offset) => {
    const sum = row.reduce((total,weight,index) => total + (raw.charCodeAt(index)-48)*weight,0);
    const remainder = sum % 11;
    return Number(raw[12+offset]) === (remainder < 2 ? 0 : 11-remainder);
  });
}
```

## Tests

- V2 Document formatting and validation: verify valid/boundary input/output and minimal consumer code against the actual helper signature.

- Verify valid numeric CPF/CNPJ and official alphanumeric CNPJ fixtures, altered first/second check digits, repeated numeric sequences and malformed values; formatter acceptance alone is never the validity assertion.

- CPF raw/display round-trip preserves an initial zero and all eleven characters; normalization is idempotent.
- Numeric CNPJ preserves leading zeros and fourteen positions; alphanumeric CNPJ preserves letters in the first twelve positions and numeric final two positions.
- Lowercase ASCII CNPJ normalizes to uppercase and formatting is idempotent. Unicode lookalikes, accented letters and letters in check-digit positions fail.
- Empty/null display yields empty text; trimmed outer whitespace is accepted but embedded whitespace, extra punctuation, malformed grouping and partial/overlength documents throw RangeError.
- A complete syntactically shaped value with incorrect check digits still formats: these helpers do not claim validity, registration or ownership.
- Reject number arguments at compile time; no parseInt/Number conversion or generic digits-only sanitizer can erase leading zeros or CNPJ letters.

## Criteria

- [x] formatCpf/normalizeCpf/formatCnpj/normalizeCnpj have one pure owner, targeted formatter/validator exports and deterministic server/client behavior without locale/provider/browser dependencies.
- [x] CPF uses eleven numeric positions and `000.000.000-00` presentation. CNPJ accepts existing numeric values and the alphanumeric structure with twelve ASCII alphanumeric positions followed by two numeric check-digit positions, presented as `AA.AAA.AAA/AAAA-00`.
- [x] Alphanumeric CNPJ support follows the [Receita Federal technical structure](https://www.gov.br/coaf/pt-br/sistemas/siscoaf/comunicados-siscoaf/atualizacao-do-portal-da-pessoa-obrigada-para-adequacao-ao-cnpj-em-formato-alfanumerico). Existing numeric CNPJs remain compatible; no digits-only transformation is applied to CNPJ.
- [x] Document values are strings, preserving leading zeros. Lowercase ASCII CNPJ letters normalize to uppercase; unexpected characters are rejected rather than silently removed or transliterated into a different identifier.
- [x] Normalizers accept raw complete strings or correctly punctuated complete strings, strip only recognized presentation punctuation and outer whitespace, and return the canonical unpunctuated string. Invalid syntax throws RangeError with no personal document echoed in the error.
- [x] Formatters accept raw or correctly formatted complete strings and return the standard punctuation. Null/empty displays return empty text; any unavailable label belongs to the consumer, not a translated helper default.
- [x] These helpers format complete identifiers. Interactive partial input, caret/selection/composition and masking remain owned by the existing MaskedInput/mask resources; callers must not run a complete-only formatter on every partial keystroke.
- [x] Formatting does not validate check digits, CPF/CNPJ status, existence or ownership and makes no backend request. A formatted identifier must not be labeled valid merely because formatting succeeded.
- [x] No new document input component, source-wide migration, logging, storage, validator dependency or duplicated generic mask engine is introduced.

- [x] Preferred public consumption uses the typed formatters/validators namespaces. Parsing and normalization functions in this source owner are internal DS exports, omitted from the root public barrel. The namespace modules alias the same owning functions rather than copying algorithms.

- [x] isValidCpf and isValidCnpj back validators.cpf/cnpj. They accept complete raw or correctly punctuated strings, check the two verification digits and reject repeated identical numeric sequences; malformed/empty/non-string inputs return false rather than throwing.
- [x] CNPJ check-digit calculation uses the official ASCII-code-minus-48 mapping for both digits and A–Z, preserving the numeric CNPJ algorithm and accepting normalized lowercase input. Use official numeric/alphanumeric fixtures plus wrong-digit mutations. [Official algorithm](https://normas.receita.fazenda.gov.br/sijut2consulta/anexoOutros.action?idArquivoBinario=76204).
- [x] Passing check digits does not establish registration, active status or ownership. Complete syntactically shaped identifiers with wrong digits still format successfully while validators reject them: presentation and validation are separate calls.

- [x] V2 **Document formatting and validation** is covered through the public TaxIdInput consumer examples and typed caller fixtures: Compare the actual formatters/validators for valid CPF, numeric CNPJ and supported alphanumeric CNPJ fixtures, plus invalid check digits. Show normalized display and validation separately; examples do not certify registration status.
- [x] V2 imports only the actual helper export or documented public helper subpath, keeps typed data valid and documents output ownership. No standalone helper route/kind, private dependency or duplicated implementation is introduced; this pending item is consumer acceptance, not loss of existing API availability.
